# Bar App Telemetry follows a written spec in this repo, not a shared package

ClaudeBar and CodexBar both write valid OTLP/JSON, but they disagree on the parts OTel leaves open: file naming, the day boundary, Sum vs Gauge for tokens, where the event name goes, and what "input tokens" includes. We pin those down in a written Telemetry Spec that lives in this repo, because the Dashboard is the one that reads the data, and each Bar App is changed to match it. We considered a shared Swift package for encoding and rejected it: the apps already have working encoders, and a spec plus a conformance PR per app costs less than a third package to version and keep in step. Telemetry that doesn't match the spec is dropped and reported in the Dashboard rather than parsed by a fallback.
